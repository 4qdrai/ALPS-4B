# ALPS-4B Two Rooms — Validated Results (local A40-class GPU)

These are real, reproduced numbers from the validation program in
`docs/VALIDATION_PLAN.md`, run locally on a CUDA GPU with a 1,200-episode
dataset (70,256 frames) generated by `data_generator.py`. They replace the
unbacked claims in the README/old report. See `scripts/run_a40_validation.sh`
to reproduce/scale on the A40.

## Before → After (the fixes work)

| Metric | Shipped `two_rooms_model.pt` | After fixes (this program) |
|---|---|---|
| G1 decoder error (held-out, world units) | **3.26** (≈ random in a 10-unit room) | **0.19 — PASS** (< 0.3) |
| G2 action sensitivity | 0.14 | **18.6** |
| G2 directional consistency | 0.50 (chance) | **1.00** (all 4 actions move decoded position correctly) |
| Two Rooms cross-room success | **0%** | **36%** (latent-graph) vs 57% oracle |

The shipped report's "0.002 units decoding error" was the latent prediction MSE
mislabeled as a position error; the true held-out decode error of the shipped
model is 3.26 world units.

## Root-cause fixes applied
1. **Real temporal input** — `frame_skip=4` (was 1; ~0.3-unit moves were near-invisible).
2. **Position-aware latent** — auxiliary position loss ON (was `pos_loss_weight=0.0`).
3. **SIGReg scaling bug fixed** — the Epps-Pulley statistic scales with row count
   `N` (`sigreg.py:94`) and was swamping all other gradients (sigreg≈400 vs pos≈1);
   now normalized per-row.
4. **Action-grounded dynamics loss** — `decode(predict_next(z,a)) ≈ next_pos`;
   this is what made actions actually move the latent (G2 sensitivity 0.14→18.6,
   directional consistency →1.00).
5. **1-step decoded-greedy control** — multi-step latent CEM rollouts drift
   off-manifold (planning worse than random); re-encoding the true frame each
   step and using only the validated 1-step dynamics navigates reliably.
6. **gate_g2 OOM fix** — mini-batched encoding (full-batch broadcast to T=8
   pseudo-clips was ~19 GB at scale).

## Gate G3 — ablation ladder (the edge), `ablation/ladder_metrics.json`
30 episodes (balanced same/cross), 1-step greedy controller, latent graph k=20.

| Rung | same-room | **cross-room** | overall | SPL |
|---|---|---|---|---|
| 0 random | 0.44 | **0.00** | 0.23 | 0.10 |
| 2 operative greedy (goal only) | 0.44 | **0.07** | 0.27 | 0.25 |
| 4a strategic [door, goal] | 0.44 | **0.21** | 0.33 | 0.32 |
| 4b **latent-graph** | 0.63 | **0.36** | 0.50 | 0.43 |
| 5 oracle (ceiling) | 1.00 | **0.57** | 0.80 | 0.80 |

**The strategic/latent-graph layer gives 5× the cross-room success of the
operative-only baseline (0.36 vs 0.07), monotonically improving toward the
oracle.** Figures: `ablation/ladder_success.png`, `ablation/latent_graph.png`.

These absolute numbers are intentionally from a small/fast local config
(d_model=128, 2,000 clips, 15 epochs, decode noise 0.19). The A40 run
(`scripts/run_a40_validation.sh`, larger model/data/epochs) should push every
rung toward the oracle ceiling.

## Gate G5 — self-learning (Latent-RAG), `self_learning_validation.json`
Honest held-out protocol (write 500 surprise contexts, test 501 unseen surprise
contexts, 1001 well-predicted control contexts):

| split | no-RAG err | with-RAG err | change |
|---|---|---|---|
| WRITE (one-shot recall) | 48.1 | 38.3 | **+20.4%** |
| TEST (generalization) | 49.1 | 39.9 | **+18.8%** |
| CONTROL (interference) | 27.7 | 34.3 | **−24.1%** |

**Verdict: NEEDS WORK** — the RAG *does* generalize to unseen similar contexts
(+18.8%, the test the shipped demo never ran), but one-shot recall is weak
(+20%, < 50% bar) and it **interferes** with already-good predictions (−24%).
This is exactly the failure mode the review predicted (the shipped
`self_learning_demo` recalled the exact stored vector for a trivial ">98%").
Concrete fix: **surprise-gated retrieval** (only add the correction when the
operative prediction error is high) plus a higher `sim_threshold` and
similarity-margin scaling, so corrections don't fire on well-predicted contexts.

## What is NOT yet shown
